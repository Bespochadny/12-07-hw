# Домашнее задание к занятию «Репликация и масштабирование. Часть 2» - Абанина Максима

## Задание 1. 
Опишите основные преимущества использования масштабирования методами:
- активный master-сервер и пассивный репликационный slave-сервер;
- master-сервер и несколько slave-серверов;
Дайте ответ в свободной форме.

1) В этой конфигурации master-сервер берет на себя всю нагрузку по чтению и записи, в то время как slave-сервер находится в «тени». Он непрерывно синхронизирует данные, но не обслуживает клиентские запросы, если только не произойдет авария. Главные преимущества: гарантированная отказоустойчивость (главное преимущество), безопасное резервное копирование, изоляция для тяжелых задач (slave-сервер, используется, как "песочница" для тяжелых процессов), простота архитектуры;
2) В этой конфигурации master-сервер по-прежнему остается единственным источником истины для операций записи, но теперь группа slave-серверов обслуживает операции чтения. Главные преимущества: горизонтальное масштабирование чтения, разделение транзакционной и аналитической нагрузки, географическое распределение, гибкость и оптимизация под определенные задачи.

## Задание 2. 
Разработайте план для выполнения горизонтального и вертикального шаринга базы данных. База данных состоит из трёх таблиц:
- пользователи,
- книги,
- магазины (столбцы произвольно).
Опишите принципы построения системы и их разграничение или разбивку между базами данных.
Пришлите блоксхему, где и что будет располагаться. Опишите, в каких режимах будут работать сервера.
1) Определение структуры таблиц:
Таблица ---- Столбцы
Пользователи ---- user_id (PK), username, email, password_hash, phone, region_id, registration_date, status
Книги ---- book_id (PK), title, author, isbn, genre_id, price, publisher, publication_year, store_id (FK)
Магазины ---- store_id (PK), store_name, address, city, region_id, phone, rating, opening_hours

2) Вертикальный шардинг — разделение по доменам
Вертикальный шардинг означает, что мы разносим целые таблицы по разным физическим базам данных в зависимости от их логической принадлежности
Вертикаль ---- База данных ---- Таблицы --- Характер нагрузки
Домен A ---- UserDB ---- пользователи 
Домен B ---- CatalogDB ---- книги 
Домен C ---- StoreDB ---- магазины

3) Горизонтальный шардинг — разделение строк внутри доменов
Горизонтальный шардинг дробит строки одной таблицы по нескольким серверам на основе ключа шардирования. Применяем его там, где объём данных или нагрузка того требуют.
Домен A — UserDB (4 шарда). Пользователей больше всего (миллионы строк), и нагрузка на эту таблицу самая высокая. Четыре шарда дают четырёхкратный запас по записи и позволяют равномерно распределить данные.
Домен B — CatalogDB (2 шарда). Книг много, но не настолько, как пользователей.
Домен C — StoreDB (1 шард, без горизонтального дробления). Магазинов в реальном мире ограниченное количество.
